## 体验与设计方向

唯一主任务：在看到真实房间的同时，用双手抓取并投掷虚拟日用品，通过可信的破碎、重量和声音释放压力。无分数激励、无倒计时、无额外音量设置。

主提案为 **“安静的现实，清晰的碎裂”**：透视房间是主画面；烟灰色实体感面板、象牙白文字、柔和浅绿触碰反馈。材质接近真实旧日用品，只有轻微磨损，没有夸张裂纹贴纸、霓虹爆炸、彩色碎屑或镜头震动。

| 候选结构 | 操作与距离 | 优点 | 拒绝或保留理由 |
| --- | --- | --- | --- |
| A：真实房间 + 上方计数 + 右下物品架 | 可及范围手指滑动，中央空间投掷 | 布局稳定，无遮挡，符合全部明确需求 | **本次提案**；需验证动态计数条的可读性 |
| B：房间内固定工作台 + 实体物品陈列 | 在约一米外工作台走近抓取 | 真实尺度强，物品陈列直观 | 增加房间占地和走动；不符合右下常驻横向面板的核心约束 |
| C：手腕工具盘 + 环绕式物品目录 | 抬手腕浏览，环绕菜单选择 | 主视野很干净 | 双手挥动时工具盘跟随，妨碍投掷且偏离既定面板位置 |

三者比较以要求符合度、中央视野占用、伸手距离、双手投掷干扰为准；B/C 是被排除的结构探索，并非待添加功能。A 尚待用户确认。

空间形态提案：**Full Space + Stage Mixed**，保留真实透视，使用空间平面进行碰撞。真实运动、物品尺度、碰撞位置和碎片堆积需要三维空间；平面屏幕只能用指针代替身体投掷，无法给出同样的动作与房间关联。计数仅需小型二维附着面板，物品架仅需可触碰的浅层面板，不将整个应用放进巨大窗口。

## 视觉系统

- Logo：开放方框被一道折线裂隙切开。线条粗细可在头显中辨识，不将真实玻璃小碎片用作字形。中文启动画面仅“碎境”，英文仅“Shatter Realm”，不附双语副标题。
- 面板：烟灰色半透明材质概念，略带实体厚度；整体暗面压住真实复杂背景，正文保持高对比。亮度适应及遮挡需实机验证，不承诺网页等同光学表现。
- 字体：简洁无衬线，中文中等字重；标题约 30、正文 20、物品标签 15 设计单位。最终 Compose 字体采用经核对授权的字体/字体资源，中文不沿用默认细字重。系统字体字形不等于系统原生控件样式。
- 品牌色：烟灰 `#222725`、象牙白 `#F4F1E8`、辅助灰绿 `#B9C1BB`、触碰浅绿 `#B9E6C5`、提示暖金 `#E6C394`。颜色为自定义品牌 token；不覆盖 SpatialUI 的 16 个原生语义角色。
- 全部按钮、面板、物品卡、刷新/重置图标采用自定义造型。**用户“禁止系统原生控件样式”优先于安装插件建议默认使用原生 SpatialUI 控件的外观要求**。后续使用 Compose 绘制定制 UI，并保留官方输入事件、无障碍语义与 PicoTheme；不使用 Material/Material3 默认外观。
- 触碰反馈：140ms 亮度/压入；面板切换 220ms 淡化；启动 Logo 约 1.6 秒。碎裂瞬间不做慢动作、自动瞄准、力度补偿或镜头移动。

### 3. 主体验与计数栏

中央区域不添加瞄准器、辅助轨迹线、倒计时或主菜单。按用户本轮反馈，上方计数面板改为**初始只显示总投掷数量**，不预先展示任何物品名或零计数。

某种物品首次成功碎裂后，才在总数右侧新增该物品名称与数量；再次碎裂只增加已有项。内置和自定义模型采用相同规则，按首次成功碎裂的顺序排列。只是选择、抓取、加载或释放而未成功碎裂，不新增计数项。

面板初始约 220×96 预览像素；随已使用种类少量横向扩展，最大约 720×96，不恢复成原先多行大面板。种类较多时，右侧明细可用官方手势射线捏合横向拖动，总数固定可见。重置后总数归零，所有物品明细收起；刷新模型不隐藏已有有效计数。上述像素用于网页设计稿，不是固定的物理单位换算。

计数名称按要求保留“总投掷数量”，但业务事件是**首次成功碎裂**：放手未撞到真实平面不增加，碎片后续碰撞不重复计数，按投掷物实例去重。重置全部清零。

物理面板尺寸提案：上方初始约 0.22 × 0.096m、最多横向展开至 0.72m，距眼约 1.35m；右下物品架约 0.48 × 0.20m，距眼约 0.65m。提示面板约 0.62 × 0.40m、距眼约 1.1m。均为待设备验证的舒适性设计值，不是固定 dp/m 换算；运行时采用官方单位转换。面板跟随视线平缓重定位，手指接触期间冻结位置，避免目标追着手移动。此平滑只作用于 UI，不修改投掷速度。

文件：`main-zh.png`、`main-en.png`；计数近景见预览主画面。

### 4. 常驻物品选择面板

右下小型横向物品架，真实材质缩略图 + 当前语言名称。同一平面排列，选中项用浅绿轮廓和选中语义标注，不按索引堆叠深度。

顺序：五件玻璃 → 五件陶瓷 → 五件电子塑料 → 按文件名稳定排序的自定义模型 → 刷新 → 重置。自定义项为空时不添加占位物品；刷新/重置仍在列表末尾，可滑到末尾触碰。

手指触碰后左右滑动浏览；捏取卡片对应物品，将模型放到实际抓取锚点并进入手持状态，避免在身体内生成。触摸滑动与捏取状态互斥，防止滑动误抓。拿取后物品架不消失。抛掷线速度、角速度均由官方追踪姿态/速度和释放时刻计算，不使用瞄准或倍率补偿。

刷新只重新索引 models 目录、生成/更新缩略图和碰撞/碎裂缓存；已拿取物体、已有碎片和计数不被刷新清除。错误文件单独跳过并提示，其余可用。

重置提案增加自定义确认弹窗防误触，确认后清空所有碎片、未持有的投掷物与全部计数；正在手持的物品回收后才完成场景清理，不留下隐形刚体。该额外确认是提案，用户可要求一触即重置。

文件：`shelf-end-zh.png`、`shelf-end-en.png`、`reset-zh.png`、`reset-en.png`。

### 5. 手柄检测提示

触发条件是**正在激活使用手柄**，不是仅连接手柄。立即停止应用消费手柄交互，以纯手势作为唯一有效输入，弹出放下手柄提示。提示内不出现必须拿手柄点击的按钮；检测到有效双手追踪后自动关闭，回到原体验状态。安全同意尚未完成时，恢复到安全弹窗，不能绕过准入。

中文：“已检测到手柄正在使用。应用已切换为纯手势交互，请放下手柄，让双手进入追踪范围。”

英文：“Active controller use detected. The app is now using hand interaction only. Set down your controllers and bring your hands into view.”

“自动切换”是应用输入策略需求，不声称已有权限强制改写系统全局输入模式。正式开发前必须通过目标 SDK 公开能力确认可配置范围；若系统限制，向用户说明实测结果，不能编造 API。

文件：`controller-zh.png`、`controller-en.png`。

### 6. 必要异常状态

- 无系统空间信息：不启动应用自定义扫描教程，不建立假地板；在物品面板提示检查系统空间信息，暂停生成新物品，现有场景保留。
- 手势追踪中断：提示双手移入范围，不根据缺失姿态生成虚假投掷速度。手中物品冻结并可恢复抓握，已有自由刚体继续物理模拟。
- 自定义目录为空：简短“暂无自定义模型”提示，内置 15 件仍可用。
- 无权限/模型损坏：逐文件失败，不清空已成功导入项或已有碎片。无应用内音量面板。

## 碎裂效果与物理原则

`concepts/fracture.png` 从左至右为落下、首次撞击、碎片沉积。该故事板只锁定“真实断裂、无霓虹特效、碎片留存”的方向，不代表精确刚体模拟结果。

- **玻璃**：薄片曲面、锋利透明断口、厚底大块与细小边片；不使用大量面向镜头的发光粒子替代几何碎片。
- **陶瓷**：釉面保留，断口露哑光陶胎；瓷片有厚度，碗底/盘足更完整。少量粉尘若后续制作，仅为短暂次要视觉，实体碎片始终是主体。
- **电子塑料**：外壳沿结构和扣件分开，屏片、键帽、支架等内构脱离；不是把所有物品都打成玻璃碎片。不模拟电池燃烧、火花、烟雾或真实危险事故。
- 首次碰到被系统识别的真实平面立即碎裂，不加冲击阈值改变用户指定规则；抓握期间忽略手持物与环境的误接触碎裂，释放后启用规则。碎片间碰撞反弹、后续投掷物与碎片碰撞均保留。投掷物仅撞到旧碎片时允许反弹，碰到真实平面后才触发首次碎裂。
- 完整物体替换成预制碎片后，各碎片有封闭几何、有效凸碰撞体、体积近似质量和惯量；总质量守恒。初始速度继承物体线速度与角速度产生的局部速度，不加“爆炸冲量”。
- 重力 9.8m/s²，米/千克/秒单位；摩擦、恢复系数按材质和接触面设计，再通过实机观察标定，不能宣传为实验级物理。
- 碎片永不自动消失；睡眠刚体保留碰撞且可被新投掷唤醒。视锥剔除仅隐藏渲染，不能移除碰撞体。不用对象池回收活碎片冒充“永久保留”。无限长会话的无限碎片会超过有限设备资源，第三阶段需实机压测并提交容量报告；任何生成上限或主动清理策略改变均需另行确认。
- 已有空间平面按官方事件同步边界和坐标；不新增扫描教学，不伪造整个无限地面。平面能力的官方说明见 [Plane detection](https://developer.picoxr.com/document/spatial-sdk/plane-detection/)。API/权限与设备支持仍需目标版本和硬件核验。

## 自定义模型的设计约束

应用根目录解释提案为 Android 应用专属文件根目录：`getExternalFilesDir(null)/models`，典型设备路径为 `/sdcard/Android/data/com.example.shatterrealm/files/models/`。**不是设备文件系统 `/models`**；不同设备以 API 实际返回路径为准。第三阶段交付目录放置说明与 adb 示例；本阶段不要求用户提供文件。

- GLB：保留米单位、材质、纹理和节点变换；FBX：需要 Android 可用的导入/转换链并核对许可证；OBJ：连同 MTL 与纹理读取，缺纹理以中性哑光材质降级。
- 运行时需真正支持三种格式，不能只改扩展名或要求用户自己全部转 GLB。优先设计为统一内部网格/PBR表示，按模型内容哈希缓存转换、凸分解与碎片几何。具体库由第三阶段能力验证后决定，暂不编造 SDK 原生支持格式列表。
- 自定义碰撞使用自动凸分解；碎裂使用网格切割/封口及碎片凸体生成，透明度/纹理尽量继承，断面为中性内材质。不接受只散发粒子或重复原模型作为“自动碎裂”。
- 非流形、开放面、极端多边形、缺单位、含动画骨架的任意模型并非天然可物理碎裂。静态网格快照、修复、失败隔离和性能预算需作为可见导入结果处理。暂不限制合法文件数量或要求用户手工预碎裂；确需限制时提交实际证据与方案。
- 自定义计数键使用稳定模型标识而非当前列表索引，刷新不会把两个不同文件的历史计数混在一起。所有自定义模型采用统一通用碎裂音效组。

## 音效设计方向及第二阶段制作清单

本阶段定义声音，不生成正式音频。无默认背景音乐，不为投掷设计夸张能量炮声音；用材质、重量、距离和碎片层叠形成反馈。

| 声音组 | 投掷 | 首次碰撞/碎裂 | 碎片落地 |
| --- | --- | --- | --- |
| 玻璃 | 轻薄短促空气声 | 清脆高频初撞 + 厚底低频碎裂 | 不规则细密玻璃轻响、渐稀疏 |
| 陶瓷 | 较沉闷的掠过声 | 瓷胎闷击 + 干脆断裂 | 有分量的瓷片敲击，较短混响 |
| 电子塑料 | 略宽、较低频空气声 | 塑料卡扣开裂 + 外壳冲击；屏片次层 | 键帽/壳片的干涩弹跳，避免玻璃感覆盖 |
| 自定义通用 | 中性短空气声 | 中性硬质断裂，弱化材质特征 | 中性碎块触地声 |

第二阶段每组每个事件至少 3 个变体，四组共 36 个样本；UI 确认、取消、选取、刷新开始、刷新完成、失败提醒、重置完成 7 个短音，共至少 43 个独立文件。导出 48kHz PCM WAV 主文件，碰撞/碎片为单声道空间声源，UI 声音轻微居中；后续按平台支持转运行时格式。

投掷声随实测速度变化，首次碰撞按接触位置发声，落地按碰撞事件与能量控制音量。允许对密集次要碎片声做短窗合并/复音管理，绝不借此删掉物理碎片。避免连续高尖峰削波；最终音量仅跟随系统，不新增音量界面。音色变体可减少重复感，不能改变物理轨迹。

## v4 补充：安装包与系统应用图标
